Phase 2 — Live Data Bridge
02A
ACSIL Study — Sierra Chart Data Publisher (C++)
Pending

A custom C++ study running inside Sierra Chart. Triggers on each closed bar and pushes OHLCV + bid/ask volume + VolumeByPrice data to the WME API. Sierra Chart stays on. No additional bridge process needed.

Approach: Use sc.MakeHTTPRequest() to POST bar data after each bar close. API key in POST header for auth. Study is a .cpp file the user adds to their Sierra Chart ACS_Source directory and applies to any chart.
Bar payload shape (full EdgeBase schema):
{ instrument, timestamp, open, high, low, close, volume, bid_vol, ask_vol, delta,
  daily_poc, daily_vah, daily_val, poc_30m, vah_30m, val_30m,

Phase 3 — Execution Intelligence + Live Session
03A
Execution Quality Score (EQS)
Future

Automatic A/B/C/D grade per trade from market context at entry. No manual input. This is the core differentiator — no competitor can produce this without per-trade order flow data.

  • EQS formula — weighted score across: wave alignment, delta confirmation, VWAP position, VP POC distance, band location
  • A/B/C/D grade thresholds — score buckets → letter grade
  • Win rate by EQS grade displayed in Analytics page
  • Grade distribution over time — trend chart (improving or drifting?)
  • Dimension breakdown — which criteria missed most often
  • EQS badge in trade modal and journal row
  • EQS filter in FilterPanel
03B
Volume Profile Analytics
Future

POC distance at entry has direct predictive value. Entries near POC are low-probability. Users discover this automatically from their own data.

  • POC distance distribution — histogram of how far entries were from session POC
  • Win rate by POC distance bucket (<5pts / 5–10pts / 10–20pts / 20pts+)
  • Value Area position at entry — inside VA / above VAH / below VAL
  • VP context in trade modal — "Entry was inside Value Area, 6pts below POC"
