Open Questions + Decisions Required
1. ACSIL study development The Sierra Chart C++ study is the only component requiring platform-specific development outside of JavaScript/TypeScript. Decision needed: build in-house vs commission from a Sierra Chart developer.
2. Instrument scope The live bar store needs to know which instrument(s) to store. Start with MNQ only, or MNQ + NQ + ES from day one? Affects schema design.
3. User authentication Currently WME is single-user. The live bar store is shared infrastructure. Multi-user means trades are user-scoped but bar data is shared. This requires auth — Supabase Auth is available but not yet implemented.
4. Wave definition for non-SC users For Sierra Chart users, wave state is computed from a specific indicator. For others, wave state is computed from EMA position. The exact EMA period and logic needs to be defined and documented.
