Eight trading journal platforms were analysed across UX, analytics depth, psychology systems, replay capability, AI integration, simplicity, mobile experience, and pricing pressure. The market falls into four archetypes.

What Every Platform Gets Wrong

  • Feature bloat — cognitive overload, low actual usage
  • Weak execution intelligence — they track outcomes, not decision quality
  • Generic analytics not adapted to discretionary scalping
  • Poor behaviour correction systems
  • Expensive pricing relative to perceived value
  • Weak mobile UX

The Biggest Market Gaps (Unowned)

1. Execution Quality Intelligence Nobody truly measures entry quality, timing precision, trade location quality, or contextual decision quality. Everyone tracks outcomes. Very few track decision quality.
2. Intraday Futures Scalping Workflow Almost nobody deeply understands NQ/ES scalpers, DOM traders, order flow traders, session-based execution, wave-based execution, or liquidity behaviour. Massive niche opportunity.
3. Behavioural Correction Engine Current systems mostly report problems. They do not correct behaviour, intervene live, or adapt coaching dynamically. There is no true "trading operating system" yet.

What Users Value Most (2026)

  1. Speed + Low Friction — minimal steps to value
  2. Actionable Insights — not just data, but what to do
  3. Behavioural Feedback — am I doing what I said I would?
  4. Clarity of Edge — does my setup actually work?
  5. Clean UX / Premium Feel — the product must feel sophisticated
Section 02

Edgeful — The Most Relevant Competitor

Edgeful is not competing with TradeZella or TraderSync. They made one brilliant strategic move: they stepped out of the post-trade journaling category entirely and attacked the pre-trade decision layer instead.

Their positioning shift From: "Track your trades" → To: "Find statistically favorable opportunities"
This is a much stronger emotional pitch. Traders care more about making money tomorrow than reviewing mistakes yesterday.

What Edgeful Excels At

  • Probability-based decision support (ORB probabilities, gap fill stats, session tendencies, bias dashboards)
  • Strong futures/scalping alignment — feels trader-native, not generic
  • Workflow integration — reports, indicators, screeners, AI, algos in one ecosystem
  • Operational trading — active during session, used during prep, used during execution

Where Edgeful Is Weak

  • Not solving trader psychology — assumes "better data = better trader"
  • Massive cognitive load risk — 150+ reports, 50+ indicators
  • Explicitly states: "it's not a trade journal" — lacks behavioural tracking, emotional logging, execution grading, discipline scoring, post-trade reflection
  • Risk of pseudo-quant retail trap — consumers of data instead of executors
  • Aggressive pricing ($49/month entry, $299/month algo tier)

Section 05

The Brainstorm

Defining The Target User

John Smith — the ideal user
  • 2–3 years of learning and trading experience
  • Understands market mechanics — structure, bias, direction
  • Can pick the right bias (knows the market is going up)
  • Problem: does not know where exactly to enter
  • Root cause: no clarity on entry parameters or entry pattern
  • Symptom: hesitation at the moment of execution
  • Platform: Sierra Chart, NinjaTrader, TradingView — could be executing on Jigsaw or Bookmap

John Smith does not have a market knowledge problem. He has a definition problem. His entry parameters exist in his head as a loose idea, not a defined, measurable checklist. When the moment comes, his brain runs a fuzzy match against vague criteria — and hesitation is what happens when the fuzzy match does not return a confident result.

The platform he uses is irrelevant to his problem. Changing platforms will not fix it.

The Manual Grading Trap

An early direction considered was building an entry checklist builder — the user defines 3–6 criteria, grades each trade, WME shows the win rate differential between full adherence and deviation.

Why this fails Manual grading is the journaling app model. Better UI, same retention problem. Traders won't do it consistently. No consistent data means no value. The loop never closes. This is exactly what every existing platform already does poorly.

Where The Loop Actually Closes

The loop closes at data capture, not post-trade tagging.

  • Journaling model: trade happens → trader remembers to tag it → data exists (maybe)
  • Closed loop: trade happens → data is captured automatically → grading is computed

For Sierra Chart users, the loop is already closed. The export contains market context at the exact moment of entry. WME does not ask the trader anything — it already knows wave state, VWAP position, Delta%, DSS, time bucket.

The question became: how do you extend that closed loop to non-Sierra Chart users?

John Smith's Two Steps

The user experience
  1. Export market data from any platform (NinjaTrader, TradingView, Sierra Chart) — standard OHLCV bars
  2. Export trade history from broker or platform — any CSV with date, direction, price, PnL

WME normalises everything. Displays the full analytical picture. Including what John Smith did not know he did not know.

The Delta Consideration

True Delta (ask volume − bid volume) requires bid/ask volume columns in the bar data. Most platforms can export this — NinjaTrader calls them UpVolume/DownVolume, others use BuyVolume/SellVolume. For platforms that cannot, WME uses a proxy calculation derived from bar structure (close position relative to high/low × volume). Directionally accurate for most analytical purposes.

Section 07

Product Positioning

What WME Is Not

  • Not a journaling app — no manual logging required
  • Not a generic analytics dashboard — no multi-asset support, no feature bloat
  • Not an AI coaching platform — no surface-level observations
  • Not a pre-trade probability tool — not competing with Edgeful

What WME Is

Post-trade execution quality intelligence for discretionary futures traders. WME tells you not just what happened — but whether you executed correctly given the market context that existed at the exact moment of your decision.

The Pitch

"You know the market. You know your setup. WME tells you whether you're actually trading it — and what it costs you when you don't."

This speaks directly to John Smith. It does not require him to learn new indicators. It meets him where he already is, with whatever platform he already uses.

Competitive Position

The industry currently asks: "What happened?"

Edgeful asks: "What should you trade next?"

WME asks: "Did you execute your edge correctly — and here is the evidence?"

Nobody is answering that third question properly. WME already has the data infrastructure to answer it. No other platform does.

Section 08

Next Steps — Build Sequence

Immediate — Platform Selector

Before any new architecture is introduced, the import page must have a clear, prominent two-path selector. Sierra Chart users and all other platform users must never see a mixed or confusing import experience.

┌─────────────────────────┐ ┌─────────────────────────┐ │ │ │ │ │ Sierra Chart │ │ Other Platform │ │ │ │ │ │ Upload your normalized │ │ Upload your raw bars │ │ XLSX or CSV export. │ │ + trade data. WME │ │ Everything is already │ │ computes everything │ │ computed. │ │ automatically. │ │ │ │ │ │ [ Select ] │ │ [ Select ] │ └─────────────────────────┘ └─────────────────────────┘

The choice persists. A small "switch" link allows changing at any time. The import page adapts to show only the relevant flow.

Phase 1 — Indicators Engine

Build lib/indicators.ts — the internal computation engine. All Sierra Chart studies replicated in JavaScript from raw OHLCV bar data. This is the core of the non-SC path.

Phase 2 — Flexible Import

New import flow for non-SC users. Column mapping UI — user identifies which column is timestamp, direction, PnL, volume, bid/ask volume (if available). WME handles the rest.

Phase 3 — Updated Normalizer

SC path: unchanged. New path calls lib/indicators.ts and produces the identical Trade and MarketBar objects the entire analytics engine already consumes. No downstream changes required.

Summary of decisions confirmed
  • Sierra Chart path remains unchanged — no disruption to existing workflow
  • Non-SC path: raw bars + trade CSV → WME computes everything internally
  • Both paths produce identical output — same analytics engine serves all users
  • Platform selector on import page — prominent, persistent, no mixed flows
  • Manual trade grading rejected — loop closes at data capture, not user input
  • Target user: John Smith — 2–3 years experience, execution consistency problem, any platform
  • Positioning: post-trade execution quality intelligence, not a journaling app
